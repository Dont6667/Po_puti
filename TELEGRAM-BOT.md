# Telegram-диспетчер «По пути»

## Что готово

Бот на **aiogram 3.31.0** получает заявки сайта и отправляет карточку обоим администраторам: `6056397902` и `5673533667`. Другие Telegram ID и групповые чаты не обслуживаются.

Карточка содержит направление, дату и время Красноярска, места, сумму, имя, номер телефона, комментарий и статус. Кнопки:

- «📋 Номер» и «📋 Имя» — нативное копирование средствами Telegram.
- «📞 Позвонить» — подписанная HTTPS-ссылка на страницу с именем и номером. На телефоне страница пробует открыть набор номера; если браузер требует дополнительное нажатие, есть большая кнопка `tel:`. Сам звонок не совершается автоматически. Имя отображается на странице; заполнение имени в системном приложении телефона зависит от контактов устройства.
- «↗ Кабинет» — существующая защищённая админка сайта, пароль по-прежнему необходим.
- Зелёное «Подтвердить» и красное «Отклонить» для новой заявки; «Отменить заявку» для подтверждённой.

Изменения выполняет сайт через **тот же `changeBooking` и ту же SQLite**, что используются веб-админкой: проверка доступности, конфликт мест, аудит, освобождение кресел при отмене. Копии отдельной базы заявок у бота нет. Статусы обновляются у второго администратора и на сайте; изменения с сайта поступают в бот при следующей синхронизации, обычно в течение 5 секунд.

## Запуск на VPS

Бот подготовлен, но для реального подключения нужен токен уже созданного бота. Токен не нужно присылать в чат и добавлять в Git.

```bash
cd ~/Po_puti
sudo bash deploy/update.sh
sudo bash deploy/setup-telegram.sh
```

Скрипт скрыто запросит токен BotFather, предложит уже заполненные два ID, создаст случайный ключ интеграции и сохранит всё в закрытом `.env` с правами `600`. Копия старого `.env` тоже сохраняется локально и исключена из Git. Ввод токена через приглашение не записывает его в историю команд. После этого скрипт собирает и запускает сайт, Caddy и контейнер бота.

**Каждый из двух администраторов должен открыть этого бота и нажать «Запустить» / `/start`.** Telegram не позволяет боту первым начать переписку. До этого попытки доставки конкретному администратору будут повторяться без потери очереди. Если этот же токен уже используется другим процессом, остановите тот процесс: для одного токена должен работать один long-polling экземпляр.

После ввода токена бот работает независимо от SSH. Профиль `COMPOSE_PROFILES=telegram` сохраняется в `.env` и применяется при следующих обычных обновлениях.

Команды бота: `/start` и `/status` — краткое состояние связи и кнопка кабинета. В обычной работе бот присылает заявки, а не периодические отчёты или сообщения о каждом перезапуске.

## Удаление через сутки и доставка после сбоев

Сообщение удаляется **через 24 часа после его отправки в конкретный чат**, с допуском интервала проверки. Подтверждение/изменение статуса не продлевает срок. Удаляются сообщения, а не записи заявок на сайте. Таймеры и идентификаторы сообщений сохраняются в отдельном Docker-томе `telegram-data`, поэтому перезапуск их не сбрасывает и обычно не создаёт повторную рассылку.

При первом запуске подхватываются заявки за предыдущие сутки. Затем сохраняются контрольная точка и очередь недоставленных ID: после временной недоступности сайта/Telegram бот догоняет пропущенные заявки, включая задержавшиеся более чем на сутки. После фактической отправки для них начинается свой 24-часовой срок. Сообщения, удалённые вручную или по сроку, повторно не отправляются. Бот хранит ID, сроки и контрольные суммы; имена/номера/комментарии в его SQLite не сохраняются.

Ограничение платформы: Telegram разрешает удалять обычные сообщения лишь пока им меньше 48 часов. Если бот не работал слишком долго, некоторые сообщения после восстановления уже нельзя удалить через API — потребуется удалить их вручную. Бот фиксирует такой случай в логах, продолжает остальные задачи и не удаляет историю сайта. Автоматическая очистка относится к сообщениям, отправленным этой версией и сохранённым в её журнале, а не к неизвестным старым сообщениям других реализаций.

Есть узкое стандартное окно возможного дубля: если Telegram принял сообщение, а процесс завершился до сохранения полученного message_id, после восстановления может прийти повтор. Абсолютную exactly-once доставку между Telegram и SQLite обещать нельзя.

## Безопасность и звонки

Токен Telegram получает только контейнер бота. Общий случайный `TELEGRAM_API_KEY` служит для внутреннего API по Docker-сети; наружный Caddy закрывает `/api/internal/telegram/*`. Все методы также проверяют ключ на самом сайте, а действия — ID администратора. Публичных портов у бота и отдельного сетевого сервера БД нет.

В ссылке звонка нет номера, имени или ключа API: только ID заявки, срок и HMAC-подпись. Страница не кешируется, запрещена для индексации, не отправляет Referrer и не содержит аналитики. Ссылка действует ограниченное время (24–48 часов от её формирования). Не публикуйте такие ссылки: это временный доступ к номеру пассажира.

Верхний уровень меню не раскрывает пароль веб-админки. Логи намеренно не содержат токенов, ключей, имён, телефонов и комментариев. Учитывайте, что текст самих заявок передаётся Telegram и виден двум разрешённым администраторам — это назначение интеграции.

## Логи, проверка и восстановление

```bash
cd ~/Po_puti
sudo docker compose -f compose.production.yaml ps
sudo docker compose -f compose.production.yaml logs -f --tail=100 telegram-bot
sudo docker compose -f compose.production.yaml exec -T telegram-bot python healthcheck.py
```

Последняя команда завершится с кодом 0 без вывода, если свежи синхронизация/long-polling и SQLite проходит `quick_check`.

При сетевых ошибках запросы повторяются; ограничения Telegram `retry_after` учитываются. Healthcheck проверяет состояние каждые 30 секунд. Внутренний watchdog контролирует цикл синхронизации и успешные getUpdates. Независимый supervisor отслеживает heartbeat даже при зависшем event loop: завершает неисправный процесс, после чего Docker с `restart: unless-stopped` поднимает контейнер. Это восстановление после сбоев, а не автоматическое исправление неправильного токена, отсутствующего интернета или физического повреждения диска.

Ручной перезапуск:

```bash
sudo docker compose -f compose.production.yaml restart telegram-bot
```

Резервная копия сайта (`sudo bash deploy/backup.sh`) теперь сохраняет и состояние доставки бота. На время копирования нужные контейнеры кратко останавливаются. Обычное обновление:

```bash
sudo bash deploy/update.sh
```

Временно остановить уведомления:

```bash
sudo docker compose -f compose.production.yaml stop telegram-bot
```

## Проверки разработки

```bash
python -m pip install -r telegram_bot/requirements.txt
python -m unittest discover -s telegram_bot -p test_bot.py -v
npm test
npm run test:seo
```

Проверяются обе доставки, отсутствие повторов при повторной синхронизации, сохранение сроков, удаление после 24 часов, изоляция посторонних ID/групп, устаревшие callback, восстановление после сетевой ошибки, watchdog, healthcheck и настоящая сериализация aiogram через локальную заглушку Bot API. Серверные тесты проверяют авторизацию интеграции, подписанную ссылку звонка, изменение заявки из Telegram, конфликт кресел и обратную синхронизацию отмены с сайта.

Локальные тесты не отправляют реальные заявки в Telegram. Полный живой smoke-test нужен после ввода токена на VPS: нажать Start обоим пользователям, оформить тестовую заявку через сайт и подтвердить её из одного чата, затем проверить статус во втором чате и веб-кабинете. Docker на локальном компьютере отсутствует, поэтому реальная контейнерная сборка/healthcheck проверяются при развёртывании.

Официальные источники: [Bot API — кнопки](https://core.telegram.org/bots/api#inlinekeyboardbutton), [ограничения удаления](https://core.telegram.org/bots/api#deletemessage), [aiogram CopyTextButton](https://docs.aiogram.dev/en/latest/api/types/copy_text_button.html).


### Меню и история в Telegram

`/start`, `/menu` и `/status` открывают одно сохраняемое меню; `/bookings` открывает историю.
Бот редактирует это сообщение при переходах, а его ID сохраняется после перезапуска.
История всех заявок из БД доступна страницами по шесть записей, с деталями и изменением статуса.
Новые заявки приходят отдельными уведомлениями и удаляются через сутки; история сохраняется.
Команды, обычный текст и вложения администраторов удаляются сразу. Поле ввода отключить невозможно.
Старые сообщения, отправленные до этого обновления и не записанные ботом, нужно удалить вручную.

Приветствие персонализировано именем администратора из Telegram. Для этого локально сохраняется его first_name (до 128 символов); в логи имя не попадает. Для маршрута используется custom emoji 5291971905690026986.
