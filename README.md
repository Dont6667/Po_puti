# По пути

Сайт пассажирских перевозок со светлой лаймовой темой, вступительной анимацией, выбором рейса и мест. Заявки, контакты, маршруты, цены и настройки сохраняются в SQLite. Государственные номера автомобилей в бронировании не используются.

## Запуск на VPS одной командой

На сервере должны быть установлены Docker Engine и Docker Compose. Загрузите эту папку на VPS и выполните из неё:

```sh
docker compose up -d --build
```

Сайт: `http://IP_СЕРВЕРА:3001`, админка: `http://IP_СЕРВЕРА:3001/admin`. Для другого порта задайте `PORT` в `.env` по образцу `.env.example`. Порт должен быть разрешён в сетевых настройках VPS.

Первый пароль генерируется автоматически. Посмотреть его:

```sh
docker compose exec website cat /app/data/admin-access.txt
```

Измените пароль в разделе «Пароль» админки. Данные входа и база не доступны через сайт. При запуске Docker создаёт новую базу и новый пароль; локальные файлы `data/` намеренно не включаются в образ.

База и загруженные изображения находятся в постоянных томах `site-data` и `site-uploads`. Пересборка и обычный `docker compose down` сохраняют их. `docker compose down -v` удаляет тома вместе с данными.

Обновление сайта после загрузки новых исходников: снова `docker compose up -d --build`. Логи: `docker compose logs -f website`. Проверка работы: `http://IP_СЕРВЕРА:3001/api/health`.

### Домен и HTTPS

Для работы через домен подключите HTTPS через обратный прокси, передающий исходный заголовок `Host` (например, в nginx: `proxy_set_header Host $http_host;`). В `.env` задайте `COOKIE_SECURE=1`, `BIND_ADDRESS=127.0.0.1` и пересоздайте контейнер командой запуска. Прокси на самом VPS направляйте на `http://127.0.0.1:3001`. При прямом HTTP-доступе оставьте `COOKIE_SECURE=0`.

### Резервная копия

Остановите сайт на время копирования SQLite, чтобы скопировать согласованную базу вместе с журналами:

```sh
docker compose stop website
mkdir -p backup/data backup/uploads
docker compose cp website:/app/data/. backup/data/
docker compose cp website:/app/public/assets/uploads/. backup/uploads/
docker compose start website
```

Храните резервную копию вне VPS: она содержит контакты пассажиров и настройки входа. Для восстановления сначала создайте контейнер (`docker compose create`), затем скопируйте папки обратно в остановленный контейнер и запустите его. Эта же процедура позволяет перенести локальные `data/` и `public/assets/uploads/` в Docker. Существующий `auth.json` сохраняет пароль админки.

## Бронирование

1. Пассажир выбирает маршрут, дату, рейс и места, вводит имя и телефон и отправляет заявку.
2. Заявка появляется в разделе «Заявки на поездки» админки со статусом ожидания. Получение заявки ещё не закрепляет места.
3. Диспетчер связывается с пассажиром и нажимает «Подтвердить места». Места становятся занятыми для данного маршрута, даты и времени.
4. Повторное подтверждение не создаёт дублей. Две заявки на одни места подтвердить нельзя. Отмена или отклонение освобождает ранее закреплённые места.

Количество пассажирских мест (по умолчанию 7), времена отправления и цены редактируются в «Рейсы и цены». Все часы рейсов и границы дат — время Красноярска, UTC+7. В форме нет оплаты, госномеров или назначения конкретного автомобиля. Уведомления в Telegram/SMS не подключены: диспетчер проверяет заявки в кабинете кнопкой «Обновить заявки».

В «Контакты» редактируются телефоны диспетчера и трансферов, часы работы, ссылки Telegram, ВКонтакте и MAX. Пустая ссылка скрывает мессенджер. После сохранения обновите открытую страницу сайта. Фотографии и автопарк редактируются в «Фотографии».

В «Водители» редактируются имя, стаж, описание и портрет каждого водителя. Можно добавлять, скрывать и удалять карточки. По умолчанию показаны тестовые данные и портреты из проекта-образца.

На главной странице один блок из трёх карточек: комфортные минивэны, стаж водителя и регулярные рейсы. Изображения карточек меняются в «Фотографии»; для машины и водителя лучше использовать PNG с прозрачным фоном. Имя и стаж берутся из первого видимого водителя в списке. Если его портрет заменён реальным фото, карточка показывает новое фото. Отдельных повторяющихся секций автопарка и команды на странице нет.

Для загрузки фото перетащите один JPG, PNG или WebP до 5 МБ на область с превью либо нажмите «Выбрать фотографию». После загрузки нажмите «Сохранить изменения». В «Фотографии» также доступны логотип, изображения трёх карточек и автомобиль в анимации.

## Локальный запуск и проверки

Требуется Node.js 24 или новее. Внешних npm-зависимостей нет.

```sh
npm start
npm run check
npm test
```

Сайт: `http://127.0.0.1:3001`, админка: `http://127.0.0.1:3001/admin`. Локальный первый пароль — в `data/admin-access.txt`. На Windows можно использовать `START-WINDOWS.cmd`.

Тесты запускают отдельный сервер и временную SQLite-базу, проверяют сохранение контактов, валидацию, авторизацию, CSRF/Origin, дубликаты заявок, конфликт и освобождение мест, сохранность после перезапуска. Рабочая база сайта не изменяется.

Некоторые статьи и расширенные справочные страницы пока открываются на исходном сайте перевозчика. Перед запуском для посетителей проверьте расписание, вместимость, цены и контактные ссылки в админке.

### Автоматическое удаление фона
Фотографии в полях «Карточка: минивэн», «Карточка: водитель» и «Водители» обрабатываются автоматически при загрузке. Получается PNG с прозрачностью; обработка выполняется на сервере, фотографии не отправляются сторонним сервисам. Фотографии трассы, маршрутов и общие фотографии сохраняют фон. Прозрачный PNG повторно не сегментируется. Одна обработка одновременно, лимит 24 миллиона пикселей, тайм-аут 120 секунд; ошибка не заменяет текущее фото.

Нужны зависимости из package-lock.json (`npm ci`); модель включена в установленный пакет. Docker использует Debian для совместимости ONNX Runtime. Для обработки рекомендуется VPS с 2 ГБ RAM. Docker-сборка на этой Windows-машине не проверялась: Docker здесь отсутствует.

Используется IMG.LY background-removal-node (AGPL-3.0): https://github.com/imgly/background-removal-js. Текст лицензии: public/licenses/background-removal-AGPL.md. Условия AGPL распространяются на интеграцию; при сетевом использовании пользователям необходимо предоставить соответствующий исходный код.
Архив исходников доступен по /source. После изменений обновите его: pwsh -File export-source.ps1. Архив содержит только исходный код; данные, пароли и загруженные фотографии исключены.

### Защита и запуск на VPS
Админка доступна по случайному постоянному адресу из data/admin-route.txt. Обычные /admin и /admin.html закрыты. Пароль и адрес находятся в data/admin-access.txt. Скрытый адрес дополняет защиту паролем. База и данные доступа находятся вне public и не раздаются сервером.
Для VPS необходимы HTTPS, COOKIE_SECURE=1 и обратный прокси; порт контейнера желательно привязать к 127.0.0.1. Сохраните volumes site-data и site-uploads и делайте резервные копии SQLite и фотографий. Публичные HTML, CSS и изображения нельзя полностью защитить от копирования.
Проверки npm test покрывают заявки, повторную отправку, подтверждение, конфликт мест, отмену, SQLite после перезапуска, Origin/CSRF, авторизацию и фотографии. Docker и HTTPS на VPS отдельно требуют проверки: Docker локально отсутствует.
