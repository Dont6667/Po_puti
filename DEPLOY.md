# Запуск на Ubuntu 24.04 / 26.04

Нужны домен с A-записью на IP VPS и открытые входящие порты 80 и 443. Если есть AAAA-запись, она тоже должна вести на этот VPS. Рекомендуется минимум 2 ГБ RAM для удаления фона.

Одна команда на свежем Ubuntu VPS (замените `example.ru` своим доменом):

```bash
sudo apt-get update && sudo apt-get install -y git && git clone https://github.com/Dont6667/Po_puti.git && cd Po_puti && bash deploy/bootstrap.sh example.ru
```

Для приватного репозитория Git запросит доступ. Используйте SSH-ключ или GitHub token; не вписывайте токен в URL.

Docker запускает сайт и SQLite, Caddy выдаёт HTTPS-сертификат. Порт 3001 наружу не публикуется. Адрес админки и новый случайный пароль выводятся после запуска. В выведенном адресе замените внутренний host на `https://example.ru`, сохранив путь `/manage-...`.

Начальные маршруты, контакты, водители и выбранные фото включены. Локальные заявки и пароль не переносятся. Начальные данные применяются только к новой базе. У существующей базы обновление сохраняет настройки.

## Обновление

```bash
cd Po_puti && sudo bash deploy/update.sh
```

Перед обновлением создаётся согласованная резервная копия базы и загруженных фото в `backups/` (сайт кратковременно останавливается). Копии содержат заявки и пароль: храните их приватно и копируйте отдельно от VPS. Обновление выполняет `git pull --ff-only`, пересобирает контейнер и проверяет его состояние. При ошибке сборки текущий контейнер продолжит работу.

Не используйте `docker compose down -v`: это удаляет постоянные данные.

## Проверка и журналы

```bash
sudo docker compose -f compose.production.yaml ps
sudo docker compose -f compose.production.yaml logs --tail=100
curl https://example.ru/api/health
```

Ожидаемый ответ: `{"ok":true}`. После запуска проверьте создание заявки, подтверждение мест, вход в админку и загрузку фотографии.

Если обновление кода не подходит, верните предыдущий коммит из `backups/<дата>/commit.txt` и выполните `sudo bash deploy/start.sh`. Не откатывайте базу поверх новых заявок без отдельного плана переноса.

Docker/HTTPS необходимо подтвердить на реальном VPS: на компьютере разработки Docker отсутствует.
