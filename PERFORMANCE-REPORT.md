# Оптимизация скорости «По пути» — 14.10.2026

Изменения подготовлены и проверены локально. Рабочий VPS обновляется командой ниже. Оценки после оптимизации получены локальным Lighthouse на Chromium Edge, а не повторным PageSpeed опубликованного сайта.

## Диагностика до изменений

Присланный [мобильный PageSpeed](https://pagespeed.web.dev/analysis/https-poputi-vmeste-ru/3p838i6lc0?form_factor=mobile): Performance 71; FCP 3,6 с; LCP 4,9 с; Speed Index 5,2 с; TBT 0 мс; CLS 0,051. Остальные категории — 100. Размер переданных ресурсов — 3 262 КиБ.

LCP-элемент — `#rec3331677601.pp-hero`, главный блок с фоновым изображением автомобилей. Он ожидал 15 внешних CSS-файлов. PageSpeed оценивает потенциальную экономию на блокирующих CSS в 3 710 мс. Критическая цепочка включала HTML → CSS → Golos TTF / Unbounded TTF. В отчёте исходный HTML передан за 71 мс, размер 11,2 КиБ; максимальная задержка цепочки — 326 мс без моделирования медленного 4G.

Network обнаружил повторную загрузку: сначала WebP 1440 px (163 КБ), затем `fleet.jpg` (2 219 КБ), который клиентский код снова назначал фоном. Два TTF занимали 962 564 байта без HTTP-сжатия. Из восьми повреждённых копий gzip-CSS браузер не применял ни одного правила; ещё два файла старого шаблона почти не использовались.

Дополнительный замер действующего VPS до публикации изменений дал 95 баллов, FCP 1,4 с, LCP 2,4 с, TBT 9 мс, CLS 0, размер 3 207 КиБ; TTFB 180 мс. Это показывает вариативность результатов: обещать фиксированные 100 баллов в каждом запуске нельзя. Сравнение локальных версий проводилось отдельно на одном браузере и компьютере.

## Сделанные изменения

- Фон первого экрана: AVIF 480/960/1440 px, WebP как запасной формат. Мобильный AVIF 960 px — 58 815 байт. Раздельный preload для мобильного и большого экрана, высокий приоритет. Фон определяется сервером и больше не заменяется исходным JPEG после запуска JS.
- Изображения в исходном HTML имеют готовые `srcset`, `sizes`, размеры и оптимизированный `src`. Главные изображения статей загружаются eagerly с высоким приоритетом; остальные фотографии — lazy. Загруженные через админку фотографии продолжают работать через исходный URL, если для них ещё нет вариантов в манифесте.
- 15 CSS-запросов заменены одним минифицированным стилем внутри HTML. Встроен весь публичный стиль, чтобы не было позднего применения оформления. Убраны десять старых подключений; нужные сбросы шаблона перенесены в `legacy-base.css`. Удаляются только классы, отсутствующие одновременно в HTML и во всех публичных JS-исходниках; классы диалога, кресел, календаря, ошибок и анимаций сохраняются.
- Два шрифта подготовлены как WOFF2 с русскими/латинскими буквами, цифрами, знаками и символом рубля: 14 368 + 26 612 = 40 980 байт вместо 962 564. Сохранён исходный экземпляр начертания 400 и прежнее браузерное выделение жирным. `font-display: swap`, ранний preload, файлы с хешами.
- Публичные JS собраны и минифицированы esbuild: один файл вместо семи, около 60 КБ без сжатия. Не подключаются старые обработчики шаблона, которые ничего не выполняли на SSR-странице. Скрипты админки и обработка фотографий не попадают в публичный браузерный пакет.
- Актуальный публичный контент и манифест изображений передаются с HTML, без ожидания дополнительного API-запроса. Карточки рейсов, автопарка, водителей и трансферов не создаются повторно после серверного рендера. Инициализация интерфейса разбита на короткие задачи.
- Заголовок и кнопки первого экрана видны сразу, в том числе без JS. Анимации карточек сохраняют движение, а текст остаётся читаемым. Декор не создаётся на размерах, где он уже скрыт дизайном; при расширении окна он появляется.
- Для секций ниже первого экрана применяется стандартный `content-visibility: auto` с запоминанием размеров. Контент остаётся в HTML и доступен навигации и поиску по странице. Это обычная браузерная оптимизация для всех посетителей: [описание web.dev](https://web.dev/articles/content-visibility).
- Node отдаёт gzip для HTML/CSS/JS/JSON/XML/SVG. Сжатые ответы повторно используются в памяти; HTML остаётся `no-store`. Хешированные ресурсы получают `Cache-Control: public, max-age=31536000, immutable`; остальные — короткое кеширование. Добавлены ETag/304 и `Vary: Accept-Encoding`.
- Docker автоматически выполняет production-сборку и удаляет зависимости сборщика из конечного образа. Caddy-конфигурация проверяется перед применением обновления.
- Удалены подписи «фото заказчика» из трёх статей. Фото дороги оформлено в горизонтальном кадре с `object-fit: cover`, без растягивания. «Подробнее о рейсе» — ровная вторичная кнопка полной ширины с высотой 46 px. Исправлены контраст двух малых надписей и доступное имя календаря.

## Сервер и безопасное развёртывание

Используется Caddy, а не Nginx: `nginx -t` здесь неприменим. Действующая конфигурация Caddy не менялась. Рабочий сайт отвечает HTTPS 200, браузер подтвердил HTTP/2; заголовок `Alt-Svc` объявляет HTTP/3, а UDP 443 уже опубликован в Compose. Доступность HTTP/3 зависит также от firewall VPS — открывать дополнительные порты для этого обновления не требуется. Сжатие Caddy `zstd gzip` сохраняется; уже сжатые ответы Node повторно не сжимаются.

На VPS:

```bash
cd ~/Po_puti
sudo bash deploy/update.sh
```

Скрипт сохраняет БД, загрузки, `.env` и номер предыдущего коммита, получает Git-обновление, проверяет Caddy, собирает образ, ждёт healthcheck и перезагружает proxy. При резервном копировании есть короткая остановка приложения. Новая сборка может занять несколько минут.

Проверка после обновления:

```bash
curl --fail https://poputi-vmeste.ru/api/health
curl -I -H 'Accept-Encoding: gzip' https://poputi-vmeste.ru/
docker compose -f compose.production.yaml ps
docker compose -f compose.production.yaml logs --tail=100 website proxy
```

Для проверки кеша откройте исходный HTML, скопируйте актуальный URL JS из `/assets/built/` и проверьте его через `curl -I`: ожидается `max-age=31536000, immutable`. У HTML ожидаются `no-store` и `Content-Encoding: gzip` при запросе gzip.

После публикации повторите PageSpeed для домена на мобильном и компьютере, желательно 3 раза. Финальная оценка VPS и реальные пользовательские Core Web Vitals пока не измерены на новой версии. Базы/пароли/DNS/домен для этой оптимизации менять не требуется.
